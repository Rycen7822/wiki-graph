# Raw-fast automation quickstart

Use this as the lightweight reference before default paper-like raw-fast clipping. It stays short: call automation, read the generated handoff, write the body draft, assemble, then close out.

## Normal flow

1. Load the project-local path exports from the ignored repository `.env` as shown in `SKILL.md`, then work from `"$WIKI_GRAPH_REPO"`. Do not read or print credentials.
2. Run `python3 -m ops.raw_fast_ingest_prepare --profile env --root "$LLM_WIKI_ROOT" --state-dir "$LLM_WIKI_STATE_DIR" --tmp-root "$LLM_WIKI_RAW_FAST_TMP_ROOT" --url <source-url>` unless the user or test fixture requires explicit overrides; the default `prod` profile bypasses `.env` for root/state. Keep the exported `LLM_WIKI_SKILL_DIR` and `LLM_WIKI_RAW_FAST_VERIFIER` so generated writing/manual references and closeout use this tracked project skill.
3. If the command succeeds, parse its JSON and read `agent_next_reads` in order: the generated `agent_handoff.md` first, then returned writing-contract refs before fallback source spans.
4. Follow the generated handoff and `automation_next_action`. Stay on generated paths; for TeX handoffs, read the generated filtered TeX source before fallback locators; for non-TeX routes, use `source_read_plan` as the handoff indicates. Do not pre-load manual/resource references or advisory sidecars unless the generated output asks for them. For social/redirect URLs, also confirm the handoff contains non-empty scientific text before drafting. HF `blob/main`-style viewer links return HTML, not the file: check `content_type`/magic bytes, resolve the canonical `resolve/main` URL, discard the false task directory, and rerun prepare; if a nominally successful prepare misclassifies downloaded HTML as a direct PDF or yields an empty digest/source surface, resolve the canonical paper URL from the original post, discard the false task directory, and rerun prepare on that canonical source.
5. Write `raw_body_draft.md` as body-only scientific reading prose. Let `candidate_frontmatter.json`, generated commands, and `ops.raw_fast_note_assemble` own YAML/frontmatter/resource-link metadata; if script-owned `domain` or metadata is wrong, stop and repair/rerun candidate generation instead of hand-editing the assembled YAML. For structured paper notes, integrate formula/objective evidence in `Methodology` and figure/table evidence in `Methodology`, `Results`, or `Limitations` with explicit prose anchors such as `目标函数`, `图表证据`, `Figure`, or `table`; for figures/tables, write the conclusion they support rather than a mechanical description of panels; the raw-fast verifier checks those narrative sections.
6. If preflight reports an existing raw duplicate for the same source, refresh that canonical raw file instead of writing the generated `next_raw_path`; preserve the original `created`, use compact allowed frontmatter only (`title`, `created`, `updated`, `type`, `domain`, `tags`, `source`, `capture_route`, `captured`, `topic_hints`), remove legacy `arxiv_*`/`source_*` extras, and run closeout against the existing `raw-file`. Before the first assemble, add the agent's semantic `tags`/`topic_hints` into `candidate_frontmatter.json` (candidate repair + `--overwrite-existing` reassemble is the seam; never hand-edit assembled YAML). If closeout already deleted the workdir, rebuild a minimal one from the canonical note, reassemble with `--overwrite-existing`, then re-mark pending via `ops.batch_wiki_integration mark-pending` with semantic `--topic-hint` values (same `raw_path` merges in place; `pending_count` must stay unchanged). After assemble, read back the refreshed canonical frontmatter because `raw_fast_note_assemble` may normalize `created` to the current date on overwrite; if that happens, restore the original `created` and rerun the verifier/final report. For already-integrated refreshes, check whether the exact title or source identifiers already appear in `_meta`/compiled pages before closeout. If they do, use a highly specific method/evidence phrase that appears only in the canonical raw note as the duplicate pattern, and verify it has exactly one wiki hit; the verifier treats `_meta` hits as non-raw duplicates. Use source URL / arXiv id patterns only when they do not appear outside raw. Verify the generated duplicate path does not exist.
7. Run generated assembly and closeout previews, normally `assemble_command.preview.sh` then `closeout_command.preview.sh` or their JSON args. Before running closeout, `cd` to a stable directory (the configured wiki-graph workdir): closeout deletes the per-task `--tmp` dir, and a shell parked inside it fails every later command (exit 126). If a `.preview.sh` is not executable, run it as `bash <preview.sh>` rather than changing workflow scope. If closeout cleanup preflight returns `refused_non_tmp_without_override` for the generated task directory under `${LLM_WIKI_RAW_FAST_TMP_ROOT}/...`, confirm the resolved path is exactly that disposable task directory, add `--allow-non-tmp-cleanup` to the closeout args/preview, and rerun; protected, wiki-root, workdir, or sensitive-home paths must remain refused. If a generated command stops, repair the script-owned input or draft it names, then rerun the generated command. If closeout already created the raw note and a repaired body draft must be re-assembled, rerun `ops.raw_fast_note_assemble` with the same generated args plus `--overwrite-existing`; do not hand-edit YAML/frontmatter. If `figure_table_inventory_style` persists without a line number, run the verifier's `VISUAL_INVENTORY_STYLE_RE` against the Methodology/Results/Limitations visual context and print the matching snippet; common false positives include unrelated Chinese phrases containing `分开` inside figure/table-bearing sections. A `formula_evidence_in_methodology`/`figure_table_evidence_integrated` blocker on a note that clearly has `$...$` math and Table/Figure anchors is usually the same class of bug: the verifier's `PLACEHOLDER_RE` (`略过`/`待补`/`未处理`/`未读…`) is a substring check that false-positives on benign text like `策略过度` (contains `略过`); grep the failing section for these substrings and reword, then rerun assemble with `--overwrite-existing`.
8. Report raw saved/refreshed, wiki queue/action, and native freshness from the closeout output's own `native_refresh_status` — do not re-run `status` or re-read reports to re-derive it. Generated closeouts carry `--defer-native-refresh` and defer the native graph refresh: the pickup trigger is `native_refresh_status.should_refresh=true` in the closeout output (the `deferred=true` marker, when visible, implies it but the reverse does not hold). When `should_refresh=true`, immediately launch the pickup `python3 -m ops.batch_wiki_integration refresh-native-after-integration --root <root> --state-dir <state-dir> --workdir <workdir>` with `terminal(background=true, notify_on_complete=true)`. Never launch the pickup while a batch closeout's auto-integration runner may still be active: that runner owns `refresh-native-after-integration` itself, and overlapping runs race in the semantic-artifact stages (stale edge-doc cleanup deletes files another stage is still reading → FileNotFoundError). Confirm the runner's terminal state (or a failed rc=13 `manual_review_required` result) before any pickup; rerun the failed path once its named blocker (e.g. `missing_topic_hints`) is repaired via candidate_frontmatter + reassemble + mark-pending. when it completes, read its final JSON and require exit code 0, `status_after.should_refresh=false`, and `active_workspace_coverage.ok=true`. For non-deferred threshold integration require the same three, plus `embedding_service.stopped=true` when the local embedding Docker is managed. Code 18 blocks cutover; code 19 requeues native refresh; codes 20/21 report managed embedding startup/configuration or shutdown failures. When wiki pending is already cleared, rerun the complete owner path with the same `refresh-native-after-integration` command; inspect only artifacts named by failure codes.

## Small parallel batch entry

For multiple papers, the parent runs `python3 -m ops.raw_fast_batch init --root "$LLM_WIKI_ROOT" --state-dir "$LLM_WIKI_STATE_DIR" --tmp-root "$LLM_WIKI_RAW_FAST_BATCH_TMP_ROOT" --url <paper-1> --url <paper-2>` and executes each returned `prepare_command`. It then runs `python3 -m ops.raw_fast_batch worker-contracts --manifest <batch_manifest.json>` and passes the returned `worker_tasks` unchanged to isolated workers. Each worker owns the same complete clipping loop as a single-paper agent: follow the generated handoff, read the required source surfaces, draft and reread the full note against the writing contract, repair its allowed semantic frontmatter, run the generated `finish-worker` command, and fix any validation failure before it reports `ready` through `worker_result.json`. The parent waits for every ready result or explicit failure, checks only script-owned worker results/contracts, item status, and source identity, and invokes `python3 -m ops.raw_fast_batch closeout --manifest <batch_manifest.json>` once. On the happy path the parent does not open paper sources, `raw_body_draft.md`, or canonical note bodies; if an item fails, it routes the generated diagnostic back to that item worker rather than performing content repair itself. Canonical publication is serialized, local threshold integration is attempted at most once after publish, external runners defer, and native refresh remains pending. Read `references/raw-fast-batch-wiki-integration.md` for report fields and recovery rules.

## Quality gate placement

The prepare JSON and generated handoff return `writing_contract_refs`; read those paths before opening fallback source spans or drafting `raw_body_draft.md`. The quality bar itself lives in `references/structured-paper-note-contract.md` section `Raw-note quality bar before closeout` plus `Minimum completeness floor`, so this quickstart stays compact but agents cannot miss the writing contract.

## Failure flow

If `raw_fast_ingest_prepare` exits nonzero, treat that as an intentional stop signal rather than guessing the next branch.

1. Parse the JSON printed by the failed command.
2. Read `manual_reason` together with returned `diagnostic_hint`, `blocker_diagnostics`, `report_path`, and `verifier_path` fields.
3. Surface the returned diagnostic path and one concise repair hint when reporting or handing off the failure.
4. When automation enters manual mode, read the paths returned in `manual_reference_paths`.
5. If no manual paths are supplied, keep the repair handoff anchored to the returned JSON/report path and its diagnostic hint.

## Completion boundary

A normal run is complete after the generated handoff has been followed, `raw_body_draft.md` has been written or an existing canonical note has been body-refreshed, `assemble_command.preview.sh` has created/refreshed the canonical raw note from script-owned metadata, generated closeout/verification has passed, and the final status clearly separates raw saved/refreshed, wiki queue/action, and graph queue/freshness.
